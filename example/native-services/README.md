# Pro Micro temperature, RNG and quadrature services

Build `others.promicro_nrf52840.example.native-services` with the board preset,
or configure this directory against the source checkout/installed package with
the matching board/toolchain. Upload is a separate procedure.

The application takes a one-shot die-temperature sample, generates 16 RNG bytes
with bias correction enabled, reads/clears QDEC counts and toggles the built-in
LED once per successful round. No flash is programmed or erased. TEMP loads the
17 factory linearity coefficients before measurements and holds HFXO for the
documented accuracy assumption. `mcubsp_die_temperature_quarters` reports signed
quarter degrees Celsius. The RNG reports only its generated byte count, not
secret material. A passing software model does not establish entropy quality.

QDEC selects P0.06 for phase A and P0.08 for phase B. Connect a 3.3 V encoder or
controlled two-phase source and common ground to observe direction/counts;
provide suitable external biasing if the encoder requires it. The LED-control
output is disconnected; the built-in LED is a separate progress indicator.
The default sample period is 128 microseconds with debounce enabled and a
10-sample report interval. `mcubsp_encoder_delta`,
`mcubsp_encoder_double_transitions` and `mcubsp_encoder_overflow` expose the
latest atomic read/clear. Floating inputs cannot qualify physical counting.

Source/host/cross-build verification and any physical observations are recorded
separately. This example is unuploaded; temperature accuracy, independent QDEC
transitions and on-device RNG observations remain pending.
